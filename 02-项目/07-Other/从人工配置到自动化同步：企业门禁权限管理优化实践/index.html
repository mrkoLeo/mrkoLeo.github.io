从人工配置到自动化同步：企业门禁权限管理优化实践

发表于 2025-11-07 分类于 02-项目 ， 07-Other 阅读次数： 本文字数： 1.8k 阅读时长 ≈ 6 分钟

记录企业门禁权限自动化改造实践。

基于 Python + 熵基门禁 API，实现门禁权限、梯控权限、卡权限的自动同步，并结合 JSON 缓存、日志留痕、权限映射等机制，解决人工开通效率低、权限容易遗漏、梯控不同步等问题。

最终将原本需要人工逐个处理的门禁开通流程，优化为可批量执行的自动化运维方案。

背景

随着企业人员规模不断扩大，门禁权限、梯控权限的开通频率越来越高。公司使用的是 熵基科技 门禁系统，设备型号为 万傲瑞达600。

由于公司内部涉及：

  • 车间门禁
  • 办公区域
  • 宿舍区域
  • 电梯梯控
  • 三辊闸
  • 摆闸

不同部门、岗位对应的权限组复杂，人工维护成本越来越高，因此开始对门禁权限同步流程进行自动化改造。

遇到问题

权限开通流程繁琐

每次新增员工或调整权限时，需要管理员：

  1. 登录门禁客户端
  2. 查询人员信息
  3. 手动核对门禁权限组
  4. 手动核对电梯权限组
  5. 同步门禁
  6. 同步梯控
  7. 配置卡号
  8. 检查是否生效

整个流程重复性极高。

痛点

权限组过多，容易配置错误

不同区域对应不同权限组：

  • 换鞋区
  • 大门
  • 客梯
  • 货梯
  • 宿舍非机动车闸机
  • 摆闸

人工勾选时非常容易遗漏。

门禁与梯控权限存在关联

某些门禁权限需要自动同步对应梯控权限。

例如：

门禁权限 对应梯控
货梯1区域 货梯1
货梯2区域 货梯2
客梯区域 客梯

人工维护时经常出现：

  • 门禁已开通
  • 电梯未同步
  • 卡权限未刷新

导致员工无法正常使用电梯。

缺少操作留痕

人工操作无法记录：

  • 谁被开通
  • 开通了哪些权限
  • 接口是否成功
  • 当前已有权限是什么

后续排查困难。

API 数据频繁查询

门禁权限组、梯控权限组数量较多。

如果每次都实时查询接口：

  • 请求慢
  • 接口压力大
  • 重复数据获取

效率较低。

问题分析

本次核心问题，本质上是：

“如何通过 API 自动化完成门禁与梯控权限同步，并减少人工操作。”

经过分析，整个流程可以拆分为：

流程 说明
获取权限组 查询所有门禁/梯控权限
查询人员 获取当前人员已有权限
权限转换 将权限名称转换为权限ID
权限合并 保留已有权限 + 新增权限
同步门禁 调用门禁同步接口
同步梯控 自动关联电梯权限
设置卡号 自动刷新卡权限
日志留痕 保存操作记录

本次采用：

  • Python
  • REST API
  • JSON缓存
  • 本地日志
  • 配置化权限同步
