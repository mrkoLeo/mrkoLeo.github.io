基于帆软报表 + MES + SpringBoot 的 Q-Time 自动化报表实战

发表于 2026-04-15 分类于 02-项目 ， 06-FR 阅读次数： 本文字数： 2.1k 阅读时长 ≈ 8 分钟

记录制造业 Q-Time 报表自动化落地实践。项目基于帆软报表、MES系统与企业内部SprinBoot平台，实现了 Q-Time 比率统计报表与 Q-Time 明细报表的自动化建设。

项目初期，统计报表与明细报表耦合在同一个模板中，由于比率统计依赖大量动态 SQL 单元格计算，导致每次打开明细报表也会触发复杂聚合查询，整体性能极差。后续通过拆分报表、建立部门—站点—工序关系模型、引入内部系统平台动态维护周期目标与责任归属，实现了报表性能优化与业务解耦。

项目难点主要包括：

  • MES Oracle 与内部系统 MySQL 双数据库联合查询
  • 工序与部门关系不在 MES 中维护
  • Q-Time 责任归属动态计算
  • 周/月/年/日多周期统计
  • 动态折线图与交叉表生成
  • 帆软动态 SQL 性能优化

最终实现：

  • Q-Time 比率统计报表
  • Q-Time 明细追踪报表
  • 内部系统 后台目标配置系统
  • 工站与部门动态维护平台
  • 多周期自动化趋势分析

有效减少了质量部门人工统计时间，提高了报表查询效率与数据准确性。

项目背景

制造工厂质量部门长期依赖人工统计 Q-Time 超时数据。

原有方式存在几个明显问题：

  • 每天/周人工导出 MES 数据
  • Excel 手工透视统计
  • 各部门责任归属不明确
  • 无法实时查看趋势
  • 周/月/年目标无法动态维护

因此提出：
构建一套基于：

  • 帆软报表
  • MES 系统
  • 内部系统 企业内部平台

的 Q-Time 自动化分析系统。

实现：

  • 自动统计
  • 自动分析
  • 自动展示
  • 自动追踪

遇到的问题

报表性能极差

最开始：

  • Q-Time 比率统计报表
  • Q-Time 明细报表

被设计在同一个模板中。

而比率统计报表：

  • 使用交叉表
  • 每个单元格都是动态 SQL
  • 每个部门 × 每个周期 都会触发一次 SQL 查询

导致：

  • 打开一次报表执行上百条 SQL
  • 明细报表每次查询都会触发统计报表
  • 页面加载极慢
  • 数据库压力巨大

MES 系统不维护部门关系

MES 系统中：

只有：

  • 工序
  • 站点
  • Lot
  • Q-Time 数据

但：

没有：

  • 部门
  • 部门与工序关系

质量部门希望：

按照部门统计责任归属。

因此必须额外建立：

  • 部门
  • 站点
  • 工序

之间的映射关系。

数据库不统一

系统涉及三个平台：

系统 数据库
MES Oracle
内部系统平台 MySQL
帆软报表 多数据源

导致：

  • 目标值在 MySQL
  • Q-Time 数据在 Oracle
  • 部门关系在 MySQL
  • 工序关系来自 MES

需要跨数据库组合查询。

周期统计复杂

需求要求支持：

  • 近2年
  • 近3个月
  • 近5周
  • 近7天

并动态生成：

  • 百分比统计
  • 趋势折线图
  • 部门对比

属于典型动态列报表。

问题分析

统计报表不应该与明细报表耦合

统计报表特点：

  • SQL 非常复杂
  • 聚合计算多
  • 查询耗时长

明细报表特点：

  • 查询频率高
  • 用户使用频繁
  • 需要快速响应

因此：

必须拆分。

最终：

  • 比率统计报表独立
  • 明细报表独立

避免互相影响。

部门与工序不应直接绑定

如果：

部门直接绑定工序。

后续：

  • MES 工序变化
  • 新增工序
  • 工艺调整

都会导致维护困难。

因此设计：

由：

  • 内部系统 维护部门与站点
  • MES 维护站点与工序

实现业务解耦。
